Assignment: Student Grades Server




This assignment uses the same skills as your professor's version (raw Node server, routing, HTML responses, forms, POST parsing), but with a different domain, and it connects to the grades code you already wrote.
Requirements

1. Spin up a Node server on port 4000, using only the built-in http module (no Express).

2. Handle these routes:
    ◦ / returns an HTML page with a short welcome message and a link to /students.
    ◦ /students returns an HTML table of students with their name, average and status (Approved/Failed), sorted from highest to lowest average. Use your existing getAverage, isStudentApproved and sorting code.
    ◦ /approved returns an HTML <ul> listing only the approved students.

3. Add a form to the /students page with these fields:
    ◦ name (text input)
    ◦ grades (text input where the user types grades separated by commas, e.g. 8, 7, 9)
    ◦ a submit button
   The form must send a POST request to /add-student.

4. Create the /add-student route that:
    ◦ reads and parses the incoming form data
    ◦ converts grades into an array of numbers
    ◦ adds the new student to your students array (in memory is fine)
    ◦ redirects back to /students so the new student appears in the table

5. Return a 404 page for any route that doesn't exist.



Differences from your professor's version (and why they matter)
• Redirect after POST: the user ends up seeing the result instead of a blank response. This is called the Post/Redirect/Get pattern and is standard in real apps.
• Data parsing beyond a string: you must split and convert grades to numbers, and think about invalid input.
• State: the server keeps data between requests, so you see how in-memory data behaves (and that it resets when the server restarts).
• 404 handling: you handle unknown routes yourself.
Bonus challenges
• Validate input: reject empty names, non-numeric grades, or grades outside 0 to 10, and show an error message on the page.
• Escape HTML: if someone enters <script> as a name, make sure it displays as text instead of running (this connects to the XSS warning about building HTML strings by hand).
• Add a /students/search?name=ali route that filters students using the query string.
• Style it with a CSS file served by your server, which means handling a /style.css route yourself.
• Redo it with Express after finishing the plain version, and compare how much code express.urlencoded() saves you.





Hints (without spoiling it)



• In plain Node, req.method and req.url tell you what was requested.
• A POST body arrives in chunks. You listen to req.on("data", ...) and req.on("end", ...) and assemble the pieces.
• A form submits data as a string like name=Ana&grades=8%2C7%2C9. The URLSearchParams class can parse it for you.
• A redirect is a 302 status with a Location header.
• Since /students and /approved both build HTML, write a helper function to avoid repeating the page layout.
Sources that can help



Core references




• MDN Web Docs (developer.mozilla.org): the best reference for HTML forms (<form>, <input>, method, action), HTTP methods, status codes, and URLSearchParams.
• Node.js official docs (nodejs.org/docs): look at the http module, especially http.createServer, IncomingMessage (req) and ServerResponse (res).
• Node.js guides (nodejs.org/en/learn): has an introduction to building an HTTP server and handling requests.
Tutorials
• The Odin Project (theodinproject.com): free, with a Node.js path that covers servers and forms.
• freeCodeCamp (freecodecamp.org): free articles and a YouTube channel with Node.js courses.
• javascript.info: great for reinforcing JS fundamentals if something in your code feels shaky.
Video
• Search YouTube for "Node.js http server tutorial" or "Node.js handle POST request without Express". Use videos for the concept, then write your own version instead of copying.
When you get stuck
• Read the error message first, then search it on Stack Overflow.
• Use console.log(req.method, req.url) at the top of your handler to see exactly what each request looks like.
• Test POST requests without the form using the browser's DevTools (Network tab) or a tool like Postman or curl.



Suggested order

2. Add routing with if/else on req.url
3. Return the HTML table for /students using your existing code
4. Add the form (it can submit to a route that only logs the data at first)
5. Parse the POST body and log it
6. Add the student to the array and redirect
7. Add the 404, then the bonus challenges
